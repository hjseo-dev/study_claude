# 예금/적금 비교

금융감독원 "금융상품 한눈에"(finlife.fss.or.kr) 오픈API로 예금 또는 적금
상품을 조회하고, 사용자가 넣으려는 금액·기간에 맞춰 실제 세후 수령액을
계산해서 가장 유리한 상품 순으로 추천한다.

API 필드 구조와 권역 코드는 [references/api-fields.md](references/api-fields.md),
이자/세금 계산 공식은 [references/interest-calc.md](references/interest-calc.md)에
정리되어 있다 — 계산은 항상 스크립트로 하고 암산하지 않는다.

## 0. 조건 확인

`$ARGUMENTS`에 "예금" 또는 "적금"이 이미 있으면 그대로 쓰고, 없으면 물어본다.
아래를 `AskUserQuestion`으로 확인한다 (이미 답이 나온 건 다시 안 물어봄).
**답을 받으면 그 즉시 같은 대화 흐름 안에서 1번(조회)으로 바로 진행한다 —
사용자에게 슬래시 커맨드를 다시 입력해달라고 요청하지 않는다.** (이 스킬은
메인 대화에서 바로 실행되므로 — 별도 백그라운드 서브에이전트로 분리하지
않는다 — `AskUserQuestion` 답변이 그대로 이어서 쓰인다.)

1. **예금 vs 적금**
2. **권역**: 1금융권(은행) / 2금융권(저축은행) / 둘 다
3. **목표 금액과 기간**:
   - 예금이면: 총 예치할 금액 (원)
   - 적금이면: 매달 납입할 금액 (원)
   - 공통: 몇 개월(또는 몇 년) 동안 넣을 건지. "1년 이상"처럼 최소 기간만
     말하면 "이상" 조건으로, "정확히 12개월"처럼 말하면 정확히 그 기간으로
     받아들인다.
4. **정렬 기준**: 기본금리 기준 예상 수령액 높은 순 / 최종금리(우대조건 다
   반영했을 때) 기준 예상 수령액 높은 순 — 표에는 기본금리·최종금리·각각의
   예상 수령액이 다 나온다. 정렬 순서만 바뀐다.

## 1. 조회

1. 환경변수 `FINLIFE_API_KEY`가 설정되어 있는지 확인한다. 없으면 아래 "인증키
   설정" 안내를 사용자에게 보여주고 중단한다.
2. 이 스킬 디렉터리의 `scripts/fetch_products.js`를 실행한다. 목표 개월수를
   같이 넘겨서 **서버(스크립트) 단에서 미리 필터링**한다 — 안 그러면 상품이
   수백~수천 개라 응답 JSON이 너무 커서 컨텍스트를 많이 잡아먹는다.

   ```
   node <스킬 디렉터리>/scripts/fetch_products.js <deposit|saving> <bank|savings-bank|both> <base|final> <개월수[+]> [상위N]
   ```

   - `<base|final>`은 0번 4번 질문(정렬 기준)의 답을 그대로 쓴다.
   - `<개월수[+]>`는 0번 3번에서 "정확히 N개월"이면 `N`, "N개월 이상"이면
     `N+`로 넘긴다.
   - `[상위N]`은 생략하면 20개.
   - 예: 적금, 1금융권, 기본금리순, 12개월 이상, 월 50만원 →
     `node .../fetch_products.js saving bank base 12+`

3. **엔드포인트가 틀렸을 가능성**: 공식 문서가 API 경로를 완전히 공개하지
   않아 스크립트 상단의 `ENDPOINTS`는 추정값이다. 실행 결과가
   `error: true`이고 메시지가 "JSON으로 해석할 수 없다"는 식이면, 엔드포인트
   자체가 틀렸을 가능성이 높다 — 이 경우 사용자에게 그대로 알리고, 필요하면
   finlife.fss.or.kr의 오픈API 문서를 다시 확인하도록 안내한다. 지어내서
   답하지 않는다.

## 2. 맞춤 계산

1번에서 받은 `products` 배열은 이미 목표 개월수로 필터링되고(또는
`nearestFallback`으로 대체됨) 정렬까지 끝난 상태다. `nearestFallback`이
`null`이 아니면 "요청하신 O개월과 정확히 일치하는 상품이 없어 가장 가까운
P개월 상품 기준으로 보여드립니다"라고 사용자에게 알린다.

`products` 배열 각 항목에 대해 `scripts/calc_maturity.js`를 실행해서 **목표
금액·개월수 기준 실제 세후 예상 수령액**을 구한다 (암산 금지, 항상
스크립트로).

```
node <스킬 디렉터리>/scripts/calc_maturity.js <deposit|saving> <금액(원)> <개월수> <연이율(%)> <단리|복리>
```

- `<개월수>`는 그 상품의 실제 `termMonths` 값을 쓴다(사용자가 "이상"으로
  요청했다면 상품마다 다를 수 있음).
- `<연이율>`은 0번 4번에서 기본금리 기준을 골랐으면 `baseRate`, 최종금리
  기준을 골랐으면 `finalRate`를 쓴다.
- `<단리|복리>`는 그 상품의 `rateType`을 그대로 넘긴다.

## 3. 결과 표시

2번에서 계산까지 끝낸 후보들을 **예상 수령액 높은 순**으로 정렬한다.
**인덱스는 1번(조회)에서 스크립트가 매긴 번호를 그대로 쓰지 않고, 이
예상 수령액 순서를 기준으로 1부터 다시 매긴다** — 그래야 화면에 보이는
순서와 인덱스 번호가 일치한다 (1번 스크립트의 인덱스는 금리 기준 정렬이라
가입기간이 다른 상품들이 섞이면 최종 표시 순서와 어긋난다). 표 컬럼:

| 인덱스 | 은행 | 상품명 | 가입기간 | 기본금리 | 최종금리 | 예상 세후 수령액 | 이자방식 | (적금만)적립유형 | (적금만)월한도 | 이벤트 | 가입대상 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- 가입기간은 `termMonths`를 "◯개월(◯년)"으로 환산해서 보여준다 (12개월 나누어 떨어지면 "1년" 같이).
- `eventGuess: true`면 "⚠ 이벤트성으로 추정"이라고 표시하고, `disclosureEndDate`가 있으면
  "(공시 종료일 참고: YYYYMMDD — 실제 이벤트 종료일과 다를 수 있음)"이라고 덧붙인다.
- `monthlyLimitGuess`가 "명시 안 됨"이면 그대로 "명시 안 됨"이라고 쓴다 — 있는 것처럼 지어내지 않는다.
- `isApproximation: true`(복리 적금)인 후보가 있으면 "복리 적금이라 실제 금액과 차이가 있을 수 있다"고 그 옆에 표시한다.
- 최종금리 기준으로 계산했다면 "최종금리는 우대조건을 다 만족했을 때 금액입니다. 조건을 못 맞추면 기본금리 기준 금액에 더 가까울 수 있어요"라고 안내한다.
- 표 아래에 반드시 이 안내를 덧붙인다: "이벤트 여부·월 한도는 API 원문에서 추정한 값이라 정확하지 않을 수 있습니다. 실제 가입 전 은행 상품설명서로 재확인하세요."

## 4. 다른 조건으로 재계산

사용자가 (2~3번에서 안 보여준) 다른 인덱스, 다른 금액, 다른 기간으로
다시 계산해달라고 하면 2번 4단계처럼 `calc_maturity.js`를 다시 실행해서
답한다. 결과를 "원금 ◯원 + 세후이자 ◯원 = 총 ◯원 수령"처럼 정리해서 답한다.

## 인증키 설정

[finlife.fss.or.kr 인증키 신청](https://finlife.fss.or.kr/finlife/api/finlifeApiKey/list.do?menuNo=700034)에서:

1. 약관 동의 → **"개인"** 선택(즉시 발급, 일일 10,000건) → 본인 확인 → 이메일 인증
2. 제출하면 즉시 발급되고, 상단 "인증키 신청결과 확인" 메뉴에서 32자리 인증키 확인
3. 12개월간 미사용 시 예고 없이 삭제될 수 있음

PowerShell (영구 설정, 새 터미널 또는 `/reload-plugins`부터 적용):

```powershell
setx FINLIFE_API_KEY "발급받은_인증키"
```

자세한 절차는 [USAGE.md](USAGE.md)에 정리되어 있다.

## 참고: 권역 코드

- `bank` = 020000 (1금융권/은행)
- `savings-bank` = 030300 (2금융권/저축은행)
- `both` = 위 두 개 동시 조회

신협/새마을금고 등 다른 2금융권을 콕 집어 요청하면, finlife API가 그 권역을
지원하는지 먼저 확인이 필요하다고 사용자에게 안내한다 (현재 스크립트는
은행/저축은행만 지원).
