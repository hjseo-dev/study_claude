# savings-compare 사용법

예금/적금 상품을 금융감독원 "금융상품 한눈에" API로 조회하고, 내가 넣으려는
금액·기간에 맞춰 실제 세후 수령액이 가장 높은 상품을 추천해주는 스킬입니다.

## 1. 사전 준비: FINLIFE_API_KEY 발급

[finlife.fss.or.kr](https://finlife.fss.or.kr/finlife/api/finlifeApiKey/list.do?menuNo=700034)
(금융감독원 "금융상품 한눈에" → 오픈API → 인증키 신청) 접속 후:

1. **약관 동의**: 오픈API 이용약관, 개인정보 수집·이용 동의
2. **이용형태 선택**: **"개인"** 선택 (개인은 신청 즉시 발급, 일일 10,000건 조회 가능 — 이 스킬 용도로 충분함. "단체"는 관리자 검토가 필요해서 시간이 걸림)
3. **본인 확인**: 페이지 안내에 따라 본인인증 진행 (공동인증서 방식이 아니라 별도 본인인증 절차 — 정확한 인증 수단은 접속 시점의 페이지 안내를 따른다)
4. **기본정보 입력**: 이메일 입력 → 이메일로 온 인증코드 입력
5. 제출하면 **개인은 즉시 인증키가 발급**된다. 화면 상단 메뉴의 **"인증키 신청결과 확인"**에서 32자리 인증키를 확인한다.

   > ⚠️ 인증키를 **12개월간 한 번도 사용하지 않으면 사전 공지 없이 삭제**된다고 안내되어 있으니, 발급 후 방치하지 말고 실제로 써본다.
   > 문의: 금감원콜센터 1332

6. 발급받은 키를 환경변수로 등록 (PowerShell, 영구 설정 - 새 터미널부터 적용됨)

   ```powershell
   setx FINLIFE_API_KEY "발급받은_인증키"
   ```

   방금 설정했다면 **새 터미널을 열거나 `/reload-plugins`** 를 실행해야
   반영됩니다.

## 2. 호출 방법

```
/wlabs:savings-compare
```

또는 예금/적금을 바로 지정:

```
/wlabs:savings-compare 적금
```

자동으로는 실행되지 않습니다 (`disable-model-invocation: true`).

## 3. 사용 흐름

1. 예금/적금, 권역(1금융권/2금융권/둘 다), **넣을 금액과 기간**, 정렬 기준(기본금리순/최종금리순)을 물어봅니다.
2. 그 기간에 맞는 상품만 추려서, 각 상품에 실제로 그 금액을 넣었을 때 세후 얼마를 받는지 미리 계산해둡니다.
3. 예상 수령액이 높은 순으로 인덱스 번호와 함께 표로 보여줍니다 (기본금리·최종금리·예상 수령액 다 표시).
4. "3번 상품 대신 30만원씩 넣으면 얼마 받아?"처럼 다른 조건으로 다시 물어보면 그 조건으로 재계산해줍니다.

## 4. 결과에서 주의할 점

- **이벤트 여부·월 납입한도**는 API가 별도 필드로 주지 않아서 상품 설명 텍스트에서
  추정한 값입니다. "명시 안 됨"이라고 나오면 정말 정보가 없는 것이고, "이벤트성으로
  추정"이라고 나와도 확정은 아닙니다.
- **공시 종료일**은 이벤트 종료일이 아니라 "이 금리 조건이 공시된 기간"입니다. 혼동하지 마세요.
- 세금은 이자소득세 15.4%(일반과세)만 계산합니다. 비과세종합저축 등에 해당하면 실제로 더 받습니다.
- 복리 적금의 만기 수령액은 근사치입니다 (정액적립식 복리는 계산이 훨씬 복잡함).
- **실제 가입 전에는 반드시 은행 상품설명서로 재확인하세요.**

## 5. 자주 겪는 문제

- **`FINLIFE_API_KEY가 설정되어 있지 않습니다` 오류**: 1번 단계를 다시 확인하고, 새 터미널 또는 `/reload-plugins`로 반영하세요.
- **"API 응답을 JSON으로 해석할 수 없습니다" 오류**: 스크립트에 적어둔 엔드포인트 URL이 실제와 다를 가능성이 큽니다 (공식 문서가 상세 스펙을 완전히 공개하지 않아 추정치로 작성됨). `references/api-fields.md`에 메모해두고 finlife.fss.or.kr 문서로 재확인이 필요합니다.

## 6. 개선/확장 아이디어

- 실제 `FINLIFE_API_KEY`로 예금/적금 × 1금융권/2금융권 × 기본금리/최종금리
  조합을 라이브로 테스트해서 정상 동작을 확인했습니다 (엔드포인트, 필드명
  전부 실제 응답과 일치). 다만 여전히 확인 못 한 것: 정확히 원하는 개월수와
  일치하는 상품이 하나도 없는 경우의 "가장 가까운 개월수로 대체" 안내 문구가
  실제로 자연스럽게 나오는지는 아직 실사용으로 확인 안 됨.
- 신협/새마을금고 등 다른 2금융권 권역은 아직 지원하지 않습니다.
- 이벤트 여부·월한도 파싱은 키워드/정규식 기반이라 정확도가 낮습니다. 실제
  사용해보고 자주 놓치는 패턴이 있으면 `scripts/fetch_products.js`의
  `EVENT_KEYWORDS`/정규식을 보강하면 좋습니다.
- 복리 적금의 정확한(근사치 아닌) 계산식을 추가하면 더 정확해집니다.
