# 🎨 브랜드 기반 컬러팔레트 선정

브랜드 자산(로고, 마스코트 사진, 기존 브랜드 컬러)에서 영감을 얻어 앱의 기본 컬러팔레트를 결정하는 스킬.

## 0. 브랜드 자산 수집

1. 사용자에게 다음을 요청한다:
   - 회사/서비스 로고 (이미지 파일)
   - 마스코트나 주요 캐릭터 사진 (있으면)
   - 기존 브랜드 컬러 정보 (있으면)
   - 원하는 디자인 톤 (미니멀/따뜨함/프리미엄/친근함 등)

2. 이미지를 기반으로 색을 추출한다 — 로고의 주요 색상, 사진 속 두드러진 색상(동물 털색 등)

## 1. 초기 팔레트 후보 제시

추출한 색상들에서 5~6개 정도의 팔레트 후보를 만든다.

각 후보마다:
- 메인 포인트 컬러 (1~2개)
- 보조 컬러
- 배경색 (밝은 버전)
- 텍스트/중성 톤

구성: HEX 코드 + 역할 명시

## 2. 대시보드 목업으로 시각화

`design-reference.html` 형태의 대시보드 샘플을 만들어서 각 팔레트가 실제 UI에서 어떻게 보이는지 보여준다.

- 사이드바 네비게이션
- 헤더 + 통계 카드
- 최근 기록 리스트
- 컬러 스와치 영역

## 3. 반복 피드백

사용자의 피드백을 받으면:
- "초록색은 싫어" → 초록 제외한 새 팔레트 만들기
- "더 밝게" / "더 어둡게" → 톤 조정
- "흰색 배경+포인트 컬러만" → 극단적으로 심플하게 재구성

각 반복마다 대시보드 목업을 업데이트해서 보여준다.

## 4. 확정

사용자가 만족하는 팔레트가 나오면 최종 색상 테이블을 정리한다:

| 역할 | 컬러명 | HEX | 용도 |
|------|--------|-----|------|
| 메인 포인트 | ... | #XXXXXX | 버튼, 헤더, 활성 상태 |
| 보조 포인트 | ... | #XXXXXX | 호버, 강조 |
| 배경 | ... | #XXXXXX | 연배경, 카드 |
| 텍스트 | ... | #XXXXXX | 본문 |

## 5. 산출물 저장

- `docs/color-palettes.html` — 최종 대시보드 목업 (아티팩트로 발행됨)
- `docs/color-palettes.json` — 색상 정보를 JSON으로 저장 (개발 단계에서 코드로 임포트 가능)
- 불필요한 실험용 파일 정리

## 주의사항

- **명도 대비**: 텍스트와 배경의 명도 차이를 충분히 (WCAG AA 기준 이상 권장)
- **다크모드 대응**: 지금은 라이트 모드 중심이지만, 나중에 다크 버전도 같은 색상으로 가능한지 미리 체크
- **시각화 > 설명**: 아무리 좋은 설명보다는 실제 대시보드 모습을 보는 게 피드백이 정확함
