# 실제 API 필드명 기록 (라이브 검증 결과)

이 문서는 `fetch_screening.js`를 실제 키로 처음 실행했을 때 확인한 응답
구조를 기록해둔다. 공식 문서와 실제 응답이 다를 수 있으므로, 여기 적힌
내용을 최신 상태로 신뢰하고 매번 재확인하지 않는다. 응답 구조가 바뀐 걸
발견하면 이 문서를 갱신한다.

## DART `fnlttSinglAcntAll.json` (재무제표 전체)

- 상태: **검증 완료** (2026-09-02, 삼성전자 005930, bsns_year=2025, reprt_code=11011, fs_div=CFS)
- 확인된 `account_nm` (필요한 계정은 모두 존재, `sj_div`로 재무제표 구분):
  - BS(재무상태표): `자산총계`, `부채총계`, `자본총계`
  - IS(손익계산서): `매출액`, `매출총이익`, `영업이익`, `당기순이익`,
    `법인세비용차감전순이익`, `기본주당이익`
  - CF(현금흐름표): `영업활동현금흐름`, `유형자산의 취득`(CAPEX로 사용),
    `재무활동현금흐름`
  - **`이자비용` 단독 항목은 없다.** 대신 IS에 `금융비용`(FinanceCosts,
    삼성전자 기준 11.7조원)과 `금융수익`(FinanceIncome)이 있다. `금융비용`은
    이자비용보다 넓은 개념(외화환산손실 등 포함)이라 이자보상배율 계산 시
    **근사치**로만 쓰고, 결과에 "금융비용 기준 근사치"라고 명시할 것.
  - `thstrm_amount`/`frmtrm_amount`/`bfefrmtrm_amount`는 모두 **문자열**이고
    콤마 없는 순수 숫자 문자열(음수는 `-` 포함, 예: `"-4480835000000"`).
    `Number()`로 바로 변환 가능.
  - CFS(연결) 조회가 대기업 기준 1차 시도에서 바로 성공했다(fallback 미발생
    확인). 비상장 자회사가 없는 소형주는 OFS만 있을 수 있으니 fallback 로직은
    유지한다.
  - `account_id`가 `-표준계정코드 미사용-`인 항목도 있다(예: `단기차입금`,
    `매각예정분류`) — `account_nm` 매칭이 더 안정적이다.

## 공공데이터포털 "금융위원회_주식시세정보" (`getStockPriceInfo`)

- 상태: **검증 완료** (2026-09-02, 삼성전자 005930, basDt=20260901)
- 확인된 필드: `srtnCd`(종목코드, 6자리 문자열), `itmsNm`(종목명),
  `mrktCtg`(시장구분, 예: `KOSPI`), `clpr`(종가), `mkp`(시가), `hipr`(고가),
  `lopr`(저가), `trqu`(거래량), `trPrc`(거래대금), `lstgStCnt`(상장주식수),
  `mrktTotAmt`(시가총액). 전부 **문자열**이고 콤마 없는 순수 숫자 문자열.
  삼성전자 예: `clpr: "261000"`, `mrktTotAmt: "1525878716688000"`,
  `lstgStCnt: "5846278608"` (261000 × 5846278608 ≈ mrktTotAmt, 교차검증 일치).
