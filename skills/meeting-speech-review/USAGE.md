# meeting-speech-review 사용법

회의/발표에서 말할 대본이나 스크립트를 주면, 5W1H 관점에서 내용이
빠짐없이 포함됐는지와 글이 아니라 "말하기"에 맞는 어순/구성으로
되어있는지 검토하고 수정안을 제시하는 스킬입니다. 별도 API 키나 외부
서비스 설정이 필요 없습니다.

> `5w1h`에 딸린 스킬이지만, `5w1h`가 문서를 저장한 뒤 자동으로 이어서
> 실행되지 않습니다. 발표 대본 검토가 필요할 때 항상 직접 호출해야
> 합니다.

## 1. 호출 방법

자동으로는 실행되지 않습니다 (`disable-model-invocation: true`). 항상
명시적으로 불러야 합니다:

```
/wlabs:meeting-speech-review
```

호출한 뒤 대화로 발표 대본 텍스트를 붙여넣으면 됩니다.

## 2. 사용 흐름

1. **참고 자료 확인**: 아래 우선순위로 내용 완결성을 판단할 기준 자료를
   확인합니다.
   1. 현재 프로젝트의 `docs/5w1h/`에 같은 주제로 보이는 `5w1h` 분석
      문서가 있으면 그 문서(특히 5W1H 항목)를 기준으로 삼습니다.
   2. 사용자가 대본과 별도로 참고 자료(데이터, 텍스트 등)를 함께 줬으면
      그것도 함께 참고합니다.
   3. 둘 다 없으면 대본 텍스트 자체만으로, 내적으로 5W1H가 빠짐없이
      언급되는지만 확인합니다(외부 사실을 새로 조사하거나 지어내지
      않습니다).
2. `references/speech-delivery-guide.md`의 체크리스트로 내용 누락과
   화법(두괄식/문장 길이/접속사 흐름/개조식 표현 등)을 점검합니다.
3. 결과를 두 부분으로 보여줍니다: **문제점 지적**(내용 누락 / 화법 두
   카테고리로 구분) → **수정된 전체 대본**(원래 화자의 말투·어휘는
   최대한 유지하고 구조와 누락 부분만 손본 버전).

## 3. 결과에서 주의할 점

- 기준 자료(5w1h 분석 문서·제공 텍스트)에도 없고 대본에도 없는 내용을
  임의로 지어내서 채우지 않습니다 — 애매하면 채팅으로 확인 질문을
  던집니다.
- 대화(발표)는 문서처럼 5W1H를 100% 채울 필요가 없다는 전제로
  검토합니다 — 기계적으로 6개 항목을 다 채우라고 요구하지 않습니다.
- 결과물은 어디까지나 "말할 대본"입니다 — 문어체 보고서로 바뀌어 있으면
  잘못된 결과입니다.

## 4. 자주 겪는 문제

- **5w1h 분석 문서가 있는데 참고가 안 됨**: `docs/5w1h/` 폴더 경로나
  파일명이 이번 주제와 다르게 보이면 못 찾을 수 있습니다 — 어떤 문서를
  기준으로 할지 직접 알려주면 그걸 씁니다.
- **자동으로 실행되길 기대했는데 안 됨**: 의도된 동작입니다. `5w1h`나
  다른 스킬이 끝났다고 자동으로 제안하지 않으므로, 매번
  `/wlabs:meeting-speech-review`를 직접 호출해야 합니다.

## 5. 개선/확장 아이디어

- 아직 실전 사용 데이터가 많지 않아서, 화법 원칙(두괄식/PREP/문장 길이
  등)이 실제로 얼마나 도움이 되는지는 여러 번 써보면서 다듬어질 수
  있습니다.
- 지금은 텍스트 기반 검토만 지원합니다 — 실제 발표 시간(분량) 제약까지
  반영해서 분량을 조절해주는 기능은 아직 없습니다.
