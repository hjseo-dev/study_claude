# 제주도 숙소 주변 여행 일정 추천

숙소 주소를 기준으로 근처 지역(읍/면/동)의 관광지·음식점을 네이버
지역검색 API(리뷰 많은 순, sort=comment)로 찾아, 사용자가 말한 박/일 수에
맞춰 날짜별 일정을 짜준다. 공식 관광지 카탈로그가 아니라 "실제 사람들이
많이 찾는 곳" 위주로 추천하는 것이 이 스킬의 핵심 목적이다.

## 실행 방법

1. **숙소 주소와 몇박 며칠인지 확인**. 사용자가 이번 대화에서 이미 둘 다
   말했다면 다시 묻지 않는다. 하나라도 없다면 먼저 물어본다 (예: "숙소
   주소(또는 숙소 이름)와 몇박 며칠 일정인지 알려주세요"). 이 스킬은 숙소
   주소를 저장하지 않으므로 매번 새로 받는다.

2. 환경변수 `NAVER_HUB_KEY_ID`, `NAVER_HUB_KEY`가 설정되어 있는지 확인한다.
   없으면 [USAGE.md](USAGE.md)의 "사전 준비" 안내를 사용자에게 보여주고
   중단한다. (cafe-with-study 스킬을 이미 쓰고 있다면 같은 키가 이미
   설정되어 있을 가능성이 높다.)

3. 이 스킬 디렉터리의 `scripts/find_places.js`를 Node.js로 실행한다.
   (스킬 로드 시 표시되는 "Base directory for this skill" 경로를 기준으로 삼는다.)

   ```
   node <스킬 디렉터리>/scripts/find_places.js "<숙소 주소 또는 숙소 이름>"
   ```

   이 스크립트는 좌표 기반 반경 검색이 아니라, 입력에서 "제주시/서귀포시 +
   읍/면/동" 지역명을 뽑아 그 지역명으로 네이버 지역검색(리뷰 많은 순,
   sort=comment)을 돌리는 방식이다. 도로명 주소든 숙소 이름이든 그대로
   넘기면 된다.

4. 응답 JSON을 확인한다.

   - `error: true`면 `message`를 그대로 전달한다. 원인이 인증키 문제로
     보이면 USAGE.md의 "자주 겪는 문제"를 참고해 다음 행동을 제안한다.
   - `needMoreInfo: true`면 입력에서 제주시/서귀포시 구분조차 못 찾은
     것이다(원도심 도로명주소처럼 읍/면/동이 안 나오는 경우는 스크립트가
     시/군 단위로 자동 대체하므로 여기 해당하지 않는다). `message`에
     안내된 대로 사용자에게 제주시 쪽인지 서귀포시 쪽인지 물어본 뒤 3번부터
     그 정보로 재실행한다.
   - 정상 응답 형식:

     ```json
     {
       "error": false,
       "needMoreInfo": false,
       "region": { "city": "제주시", "area": "애월읍" },
       "resolvedLodgingAddress": "...",
       "broadenedToCityLevel": false,
       "attractions": [
         { "title": "...", "category": "여행,명소>관광,명소", "address": "...", "telephone": "...", "link": "..." }
       ],
       "restaurants": [ { "title": "...", "category": "음식점>...", "address": "...", "...": "..." } ]
     }
     ```

   - `category` 필드를 보고 관광지/음식점과 무관해 보이는 항목(병원, 부동산,
     학원 등 검색어가 잘못 걸린 경우)이 섞여 있으면 그 항목은 제외하고
     사용한다.
   - `attractions`와 `restaurants`가 둘 다 비어 있으면(시/군 단위까지
     넓혀봤는데도 결과 없음, `broadenedToCityLevel: true`인데도 비어있는
     경우) 숙소 주소/지역명이 정확한지 사용자에게 확인을 구한다.
   - 결과가 있지만 둘 중 하나가 너무 적으면(예: 관광지 2곳뿐) 있는 것만
     가지고 일정을 짜되, 부족하다는 점을 한 줄로 알려준다.

5. **일정 짜기** (`attractions` + `restaurants` 목록과 요청받은 박/일 수를
   근거로 Claude가 직접 구성한다 — 스크립트는 날짜 배치를 하지 않는다):

   - 하루당 관광지 2~3곳 + 식사(음식점 목록에서) 2끼(점심/저녁, 필요시
     아침도) 정도를 기본 분량으로 잡는다. N박 (N+1)일이면 총 N+1일치를
     짠다(마지막 날은 이동/체크아웃을 고려해 분량을 절반 정도로 줄인다).
   - **지리적으로 가까운 곳끼리 묶는다**: 좌표/거리 데이터가 없으므로, 각
     항목의 `address` 문자열에 나오는 지역명(예: "○○읍", "○○동", "○○리")이
     숙소와 같거나 인접해 보이는 것끼리 같은 날에 배치하는 상식적 판단으로
     묶는다. 하루 동선이 제주도를 가로질러 왔다갔다하지 않게 하는 게
     목적이다. `broadenedToCityLevel: true`로 시/군 단위까지 넓혀서 받은
     결과라면, 숙소와 같은 읍/면/동 항목을 우선 배치하고 더 먼 지역명
     항목은 뒤쪽 날짜로 미룬다.
   - 같은 장소를 여러 날에 중복 배치하지 않는다.
   - 결과는 `sort=comment`(리뷰 많은 순)로 조회한 것이므로, 각 카테고리
     안에서 앞쪽에 나온 항목일수록 리뷰가 많은(더 대중적인) 곳이라고 봐도
     된다 — 일정에 다 못 넣을 만큼 후보가 많으면 앞쪽 항목을 우선
     채택한다. 다만 API가 주지 않는 세부 평점·최신 리뷰 내용까지 안다고
     단정하지는 않는다.
   - 운영시간/휴무일/예약 필요 여부는 API에서 제공하지 않으므로, 결과
     마지막에 "출발 전 운영시간·휴무일을 다시 확인하라"는 안내를 한 줄
     덧붙인다.

6. **결과 정리**: `Day 1`, `Day 2`, ... 형식으로 날짜별 오전/점심/오후/저녁
   블록에 장소 이름과 지역명(예: 애월읍)을 적는다. 각 줄 앞에 어울리는
   이모지를 붙인다(🏞️ 관광지, 🍽️ 식사). 전체 일정에서 가장 추천하고 싶은
   하이라이트 한 곳이 있으면 그 줄만 "⭐ "로 시작한다.

7. 사용자가 "숙소 바꿔줘", "일정 다시 짜줘", "박수 바꿔서" 등으로 요청하면
   1번부터 새 값을 물어보고 다시 진행한다(저장된 값을 덮어쓰지 않는다 —
   애초에 저장하지 않기 때문).
