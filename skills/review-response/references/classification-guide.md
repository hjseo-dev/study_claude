# 리뷰 코멘트 분류 기준

## 1. 심각도 라벨 정규화

회사 리뷰 도구마다 표기가 다를 수 있다. 아래 매핑을 참고해 Critical/
Medium/Low 셋으로 정규화한다:

| 자주 쓰이는 표기 | 정규화 |
|---|---|
| Critical, Blocker, Must Fix, P0 | Critical |
| Major, Should Fix, P1 | Medium |
| Minor, Nit, Suggestion, P2 | Low |

라벨이 아예 없으면(자유 서술형 리뷰) 추측하지 말고 사용자에게 이 코멘트의
심각도를 물어본다.

## 2. Critical — 무조건 반영

보수적인 회사 리뷰에서 Critical/Blocker로 표시된 항목은 이미 리뷰어(또는
리뷰 도구)가 신중하게 판단한 결과라는 전제로 다룬다. 이 스킬은 Critical을
재판단하지 않는다 — 3단계(코멘트별 검토)는 "어떻게 반영할지"를 파악하기
위해서만 하고, "반영할지 말지"는 이미 결정된 것으로 취급한다.

## 3. Medium — 3분류

1. **반영해야 함**: 조사 결과 실제로 타당한 지적. 개선 방향을 제시한다.
2. **범위 밖/중요도 낮음**: 이번 작업의 목적과 무관하거나, 관련은 있어도
   지금 당장 급하지 않은 경우. 왜 범위 밖인지(5w1h 문서의 What/범위외를
   인용할 수 있으면 인용) 반박 근거를 남긴다.
3. **확인 필요(틀림 또는 의도된 설계일 가능성)**: 리뷰가 사실과 다르거나,
   지금 구조가 의도적인 선택(트레이드오프)일 수 있는 경우. **이 판단은
   AI가 프로젝트의 숨은 맥락(과거 논의, 비즈니스 제약 등)을 모를 수 있어
   확신할 수 없다** — 반드시 "확인 필요"로 표시하고, 왜 그렇게 의심되는지
   (반박 근거 초안)는 적어주되 최종 결정은 사용자 몫으로 남긴다.

## 4. Low — 2분류 (+ 확인 필요는 공통)

1. **적용 추천**: 사소하지만 고쳐두면 확실히 나은 경우.
2. **적용 안 해도 무방**: 스타일 취향 수준이거나 효과가 미미한 경우.

Low도 조사 중 "이거 사실 리뷰가 잘못 안 것 같은데?" 싶으면 Medium의 3번과
동일하게 확인 필요로 표시한다.

## 5. 연관 코드 추적 시 체크할 것

- 리뷰가 지적한 코드를 고치면 그 코드의 호출부가 영향받는가?
- 같은 파일/모듈 안에 이 지적과 똑같은 패턴이 반복되는 곳이 더 있는가?
  (하나만 고치고 나머지는 안 고치면 일관성이 깨짐)
- 이 코멘트에 대응해서 코드를 고친다면, 그 변경 자체가 다른 리뷰
  코멘트(이번 회차의 다른 항목)와 충돌하지는 않는가?

## 6. 반영/미반영 근거 작성 원칙

- "반영해야 함"이어도 그냥 "맞는 말이라 반영"이 아니라, **왜 맞는지**
  (구체적으로 어떤 문제가 실제로 발생하는지)를 적는다.
- "반영 안 함"이면 **왜 아닌지**를 구체적으로 적는다 — "이미 확인했지만
  문제 없음"이라고만 쓰지 않고, 어떤 근거로 문제 없다고 판단했는지
  적는다.
- 근거 없는 반영/미반영 판단은 이 스킬의 산출물로 인정하지 않는다.

## 7. 개선 코드는 리뷰어의 제안을 그대로 베끼지 않는다

회사 리뷰(특히 AI 리뷰어)는 제안 코드를 함께 주는 경우가 많다. 이건
참고 자료일 뿐, 그대로 채택하지 않는다:

- 리뷰어가 이 프로젝트의 실제 컨벤션(네이밍, 계층 구조, 에러 처리 방식,
  이미 쓰고 있는 유틸/패턴)을 모르고 일반적인 스타일로 제안했을 수
  있다 — 2단계에서 확보한 프로젝트 컨텍스트에 맞게 다시 작성한다.
- 리뷰어는 이 코드의 호출부·연관 모듈까지는 못 봤을 수 있다 — 3단계
  조사 결과(호출부 영향)를 반영해서, 리뷰어의 제안보다 더 안전한
  형태로 다듬는다.
- 리뷰어의 제안이 이미 이 프로젝트 컨벤션과 잘 맞고 사이드이펙트도
  없다면, 그대로 채택해도 된다 — 무조건 다르게 쓰라는 뜻이 아니라,
  검증 없이 베끼지 말라는 뜻이다.

## 8. 회차가 거듭될 때

- 새 회차의 코멘트가 이전 회차에서 "범위 밖" 또는 "확인 필요"로 처리한
  항목에 대한 반박/재지적이면, 이전 회차의 근거를 인용하면서 왜 유지
  되는지(또는 이번엔 판단이 바뀌는지) 설명한다 — 이전 판단을 못 본 척
  다시 처음부터 판단하지 않는다.
- 리뷰어가 이전 반박을 받아들이지 않고 계속 같은 지적을 반복하면, 이건
  Medium 3번(확인 필요)로 격상해서 사용자에게 직접 판단을 요청하는 걸
  고려한다 — AI 대 AI(또는 AI 대 리뷰어)로 같은 논쟁을 무한히 반복하지
  않는다.
