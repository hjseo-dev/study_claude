# readme-creator 사용법

프로젝트 코드베이스를 실제로 스캔해서 근거를 찾은 뒤, 프로젝트 설명·기술
스택(선택 이유 포함)·실행 방법·주요 구현·트러블슈팅·데모/이미지 6개 항목
체크리스트로 `README.md`를 작성/갱신하는 스킬입니다. 추측으로 채우지 않고,
근거를 찾을 수 없는 항목(특히 기술 선택 이유)은 사용자에게 되묻습니다.

## 1. 호출 방법

`disable-model-invocation: false`라서 슬래시 명령과 자연어 요청 둘 다
됩니다.

```
/myskill:readme-creator
```

또는 "README 작성해줘", "README 최신화해줘" 같은 말로도 자동 실행됩니다.

## 2. 사용 흐름

1. **프로젝트 스캔**: `package.json`/`build.gradle`/`pom.xml`/
   `requirements.txt` 등에서 기술 스택과 버전을 확인하고, 폴더 구조로
   프론트/백엔드/DB 구성을 파악합니다. `docs/` 아래 설계 문서(스키마, API
   명세, 화면 설계)가 있으면 "주요 구현" 섹션 근거로, git log/최근 커밋으로
   실제 구현된 기능 범위를 확인합니다(계획만 있고 미구현인 것과 구분).
2. 6개 체크리스트 항목을 항목별 작성 원칙에 따라 채웁니다.
   - **기술 스택**: 각 기술마다 "왜 이걸 골랐는지"를 한 줄로 붙입니다.
     코드/대화에서 근거를 찾을 수 없으면 추측하지 않고 사용자에게 물어봅니다.
   - **트러블슈팅**: 처음 작성 시점에는 비워두거나 "아직 없음"으로 둡니다.
   - **데모/이미지**: 스크린샷 경로나 배포 URL을 사용자에게 확인해서
     링크하고, 없으면 섹션을 생략하거나 "추가 예정"으로 표시합니다.
3. 프로젝트 루트의 `README.md`에 씁니다 — 기존 파일이 있으면 구조를
   유지하며 업데이트하고, 없으면 새로 만듭니다.

## 3. 트러블슈팅 섹션 재호출 시 동작

이미 트러블슈팅 항목이 있는 `README.md`에 다시 `readme-creator`를 호출하면,
새 항목을 추가할 수 있는지 먼저 사용자에게 확인합니다 — 기존 항목을
말없이 덮어쓰지 않습니다.

## 4. 유의사항

- 코드에 없는 기능을 "구현됨"으로 적지 않습니다 — 설계만 된 것과 실제
  구현된 것을 구분합니다.
- 트러블슈팅은 사용자가 알려주기 전까지 지어내지 않습니다.
- 기술 선택 이유는 사용자 확인 없이 추측하지 않습니다 — 애매하면 질문합니다.
