# /bookmark

사용자가 준 웹 URL의 내용을 읽고, 정리해서 로컬 `D:\project\bookmark` 폴더에 마크다운 파일로 저장한다.

## 0. 트리거

- `/bookmark`만 입력됨 ($ARGUMENTS 없음): 정확히 다음 문구만 보내고 사용자의 다음 메시지(URL)를 기다린다.
  ```
  URL을 입력하세요.
  ```
- `/bookmark <url>` 처럼 $ARGUMENTS에 URL이 바로 포함된 경우: 프롬프트 없이 바로 처리한다.

## 1. 내용 가져오기

1. 먼저 WebFetch로 URL 내용을 가져온다.
2. WebFetch가 403/차단/도메인 제한 등으로 실패하면 바로 포기하지 말고, Bash 또는 PowerShell로 일반 데스크톱 브라우저 User-Agent를 붙여 curl(또는 `Invoke-WebRequest -UserAgent ...`)로 재시도한다. 스크래치패드 디렉토리에 저장한 뒤 Read로 직접 읽어 제목/본문을 파악한다 (예: 네이버 블로그는 `se-main-container`, 일부 레시피 사이트는 `<meta name="description">`에 본문 전체가 들어있는 경우가 있으니 확인).
   ```
   curl -s -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36" "<URL>" -o <스크래치패드>/fetch.html
   ```
3. 이 방법도 실패하거나(진짜 로그인 필요, 캡차, 명백한 접근 차단 신호) 내용을 신뢰할 수 없으면, 내용을 지어내지 말고 사용자에게 실패 사실을 알리고 페이지 내용을 직접 붙여넣어 달라고 요청한다.

## 2. 이미지 가져오기

원문 HTML(1번에서 curl로 받아둔 파일, 또는 필요시 재요청)에서 이미지를 추출해 함께 저장한다. 페이지의 `<img>` 태그는 대부분 로고/아이콘/광고/트래킹 픽셀이라 그대로 다 받으면 안 되고, 아래 순서로 신뢰도 높은 것만 고른다.

1. **본문 이미지**: 본문으로 판단한 컨테이너(예: `se-main-container`) 안에 있는 `<img src>`만 후보로 삼는다.
2. **노이즈 제외**: 아래에 해당하면 후보에서 제외한다.
   - 파일명/속성/클래스에 `icon`, `logo`, `btn`, `sprite`, `pixel`, `tracker`, `qrcode`, `sns_` 등이 포함된 경우
   - width/height가 32px 이하로 명시된 경우
   - `data:` URI (base64 인라인 이미지)
3. **개수 제한**: 문서 등장 순서 기준으로 최대 **5장**까지만.
4. **다운로드**: 상대경로 이미지 URL은 페이지 URL 기준으로 절대경로로 변환한 뒤, "1. 내용 가져오기"와 같은 User-Agent로 curl 다운로드한다.
   ```
   curl -s -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36" "<이미지 절대 URL>" -o "D:\project\bookmark\<주제 폴더>\images\<파일명>-<순번>.<확장자>"
   ```
5. 개별 이미지 다운로드가 실패해도 전체 작업을 중단하지 않고 그 이미지만 건너뛴다. 페이지에 쓸만한 이미지가 없으면 이 단계는 건너뛴다.

## 3. 중복 확인

- `D:\project\bookmark\INDEX.md`를 읽어 같은 URL이 이미 있는지 확인한다.
- 이미 있으면 사용자에게 다음 세 가지 중 하나를 선택하게 한다 (AskUserQuestion 사용):
  - **a. 무시** — 아무 작업도 하지 않고 종료
  - **b. 업데이트** — 페이지를 새로 가져와 기존 문서를 완전히 새로 작성(덮어쓰기)
  - **c. 추가된 내용만 업데이트** — 기존 문서(사용자가 손댄 내용 포함)는 그대로 두고, 원문에서 기존 문서에 없는 새 내용만 찾아 추가
- 새 URL이면 바로 4번으로 진행한다.

## 4. 주제(폴더) 분류

- `D:\project\bookmark` 아래의 기존 하위 폴더 목록을 확인한다.
- 가져온 내용과 잘 맞는 기존 폴더가 있으면 그 폴더를 재사용한다.
- 마땅한 폴더가 없을 때만 적절한 이름의 새 폴더를 만든다. (폴더가 계속 늘어나 비슷한 주제가 쪼개지지 않도록 기존 폴더를 우선 검토)

## 5. 문서 작성

다음 형식으로 마크다운 문서를 만든다. (기준 사례: `D:\project\bookmark\Claude-Code\2026-08-29_Claude-Code-모범-사례.md`)

```markdown
# {제목}

- URL: {원본 URL}
- 저장일: {YYYY-MM-DD}
- 태그: [{태그1}, {태그2}, ...]

## 요약

{핵심 내용을 3줄 이하로}

## 핵심 내용

{원문 구조(소제목)를 따라가며 재구성.
- 표로 정리하는 게 나은 내용(비교, Before/After 등)은 표로
- 코드는 코드 블록으로
- 줄글은 소제목(### 등)으로 본문과 구분되게
- 분량은 원문 길이와 중요도에 맞게 판단 — 가장 중요한 내용을 남기는 것이 우선
- 2번에서 받은 본문 이미지는 원문에서 등장하던 위치와 가장 가까운 섹션에 `![설명](./images/{파일명}-{순번}.{확장자})`로 삽입. 위치를 특정하기 애매하면 핵심 내용 섹션 끝에 모아서 배치}

## 관련 링크

{원문에 관련 링크 섹션이 있으면 그대로 정리}

---

<div style="font-size:0.85em;color:#888888">

**생략된 내용 (원문에는 있으나 이 문서에는 정리하지 않음)**
- {빠진 소제목/섹션을 정직하게 나열. 없으면 이 블록 자체를 생략}

</div>
```

- **태그**: 최소 2개, 최대 5개. 너무 일반적인 태그(예: "웹", "정보")는 피하고 내용을 실제로 대표하는 것으로 선정.
- **요약**: 반드시 3줄 이하.

## 6. 파일명 규칙

`{YYYY-MM-DD}_{정제된 제목}.md`

정제 규칙:
1. 제목의 공백 → `-`
2. Windows 금지 문자 제거: `\ / : * ? " < > |`
3. 연속된 하이픈은 하나로 축약
4. 앞부분 기준 최대 50자로 자르기

경로: `D:\project\bookmark\<주제 폴더>\<파일명>.md`
이미지 경로: `D:\project\bookmark\<주제 폴더>\images\<파일명>-<순번>.<확장자>`

## 7. 인덱스 갱신

`D:\project\bookmark\INDEX.md`의 표(저장일 | 제목 | 주제 | 태그 | 경로 | URL)를 갱신한다.

- 신규 저장: 새 행 추가
- 3번에서 b 또는 c를 선택한 업데이트: 같은 URL의 기존 행을 갱신 (새 행 추가 금지, 중복 행 방지)

## 8. 완료 보고

저장한 파일 경로와 폴더, 다운로드한 이미지 수를 알려주고, 5번에서 "생략된 내용"이 있었다면 함께 언급한다.
