# 회의 발표 대본 검토

사용자가 회의/발표에서 말할 대본(구어체 텍스트)을 주면, 다음 두 관점에서 검토하고 수정안을 제시한다.

1. **내용 완결성** — 5W1H 관점에서 빠진 내용이 없는지 (대화체 특성상 100% 다 채울 필요는 없다는 전제 하에, 핵심 누락만 짚는다)
2. **구어체 구성** — 글이 아니라 "말하기"에 맞는 어순/순서로 되어있는지 (두괄식, 문장 길이, 흐름 안내 등)

체크리스트와 원칙은 [references/speech-delivery-guide.md](references/speech-delivery-guide.md)에 정리되어 있다 — 검토 전에 반드시 읽는다.

## 0. 참고 자료 확인 (우선순위)

내용 완결성을 판단할 기준 자료를 아래 우선순위로 확인한다:

1. **spec-writer 분석문서** — 현재 프로젝트의 `docs/analysis/`에 같은 주제로 보이는 분석 문서가 있으면 그 문서(특히 5W1H 항목)를 기준 자료로 삼아 대조한다.
2. **사용자가 제공한 별도 데이터/텍스트** — 사용자가 발표 대본과 별도로 참고 자료(데이터, 텍스트 등)를 함께 줬으면 그것도 기준 자료로 함께 참고한다.
3. **위 둘 다 없으면** — 발표 대본 텍스트 자체만으로 5W1H 항목이 내적으로 빠짐없이 언급되는지만 확인한다 (외부 사실을 새로 조사하거나 지어내지 않는다).

기준 자료가 여러 개(분석문서 + 제공 텍스트)면 둘 다 반영한다. 어떤 걸 기준으로 삼았는지 검토 결과에 명시한다.

## 1. 검토

1. `references/speech-delivery-guide.md`의 5W1H 체크리스트로 대본 내용을 점검한다. 0번에서 확보한 기준 자료가 있으면 그 내용과 대조해서 "언급됐어야 하는데 빠진 내용"을 찾는다. 기준 자료가 없으면 대본 자체 안에서 논리적으로 비어 보이는 부분만 짚는다.
2. `references/speech-delivery-guide.md`의 화법 원칙(두괄식/문장 길이/접속사 흐름 등)으로 어순·구성을 점검한다. 글쓰기 관용구(예: "~함", 개조식 나열)가 구어체로 안 바뀐 부분이 있으면 짚는다.
3. 지어내지 않는다 — 기준 자료에도 없고 대본에도 없는 내용을 "이것도 넣어라"고 임의로 요구하지 않는다. 애매하면 사용자에게 물어본다.

## 2. 결과 제시

아래 순서로 보여준다:

1. **문제점 지적** — 내용 누락 / 화법(어순·구성) 두 카테고리로 나눠서, 무엇이 왜 문제인지 짧게 설명한다.
2. **수정된 전체 대본** — 지적한 문제를 반영해 다시 쓴 전체 텍스트. 원래 화자의 말투/어휘는 최대한 유지하고, 구조와 누락 부분만 손본다.

## Anti-patterns

- 대본이 아닌 문어체 보고서로 다시 쓰지 않는다 — 어디까지나 "말할 대본"이다.
- 기준 자료 없이 5W1H를 억지로 다 채우라고 요구하지 않는다 (대화는 100% 충족 안 해도 된다는 전제).
- 분석문서/제공 텍스트가 여러 개라 어떤 걸 기준으로 할지 애매하면 추측하지 말고 사용자에게 물어본다.
