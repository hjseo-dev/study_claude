# 시각화 스타일 가이드

wlabs 스킬들이 결과를 **HTML Artifact**(비교 페이지, 대시보드, 리포트 등)로
시각화할 때 기본으로 따르는 디자인 방향이다. 4개 레퍼런스를 실제로 열어보고
정리했다:

- 손그림 화이트보드 다이어그램(마커 선 + 손글씨 라벨 + 포인트 컬러 1개)
- 알약(pill) 모양 토글 스위치의 스냅 애니메이션(고대비 흑백)
- persona-studio.com — 아이소메트릭 야간 도시 온보딩 투어(따뜻한 조명, 말풍선 가이드 캐릭터, 달성도 트래커)
- mobbin.com — 직접 접속은 막혀 확인 못 했음. 일반적으로 알려진 특징(무채색 배경, 카드 그리드, 절제된 컬러)만 참고용으로 반영

## 적용 범위 — 중요

**Mermaid 코드 블록(문서 안에 `\`\`\`mermaid`로 박히는 다이어그램)에는 이 가이드를
적용할 수 없다.** Mermaid는 노드-화살표 문법이라 손그림 질감·애니메이션·커스텀
폰트를 못 담는다 — 지금처럼 심플한 `sequenceDiagram` 등을 그대로 쓴다.

이 가이드는 **HTML Artifact를 만들 때만** 기본 방향으로 삼는다(예: 두 문서
비교 페이지, 스킬 테스트 결과 리포트, 프로젝트 구조를 한눈에 보여주는
대시보드 등).

## 컬러 팔레트

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--paper` | `#f6f3ec` | `#15181a` | 배경(살짝 따뜻한 무채색 — 순백/순흑 아님) |
| `--surface` | `#ffffff` | `#1b1f21` | 카드/패널 |
| `--ink` | `#1e2119` | `#e8e4da` | 본문 텍스트 |
| `--muted` | `#6f6a5c` | `#9c968a` | 보조 텍스트 |
| `--line` | `#e2dbc9` | `#2c3230` | 테두리/구분선 |
| `--accent` (teal) | `#0f6e63` | `#57d6c4` | 주요 강조 — 확인됨/새로움/포인트 |
| `--warm` (amber) | `#b2530c` | `#f0ab6c` | 보조 강조 — 발견/성취/따뜻한 디테일 |

두 강조색(teal/amber) 중 **한 페이지에 하나를 주인공으로 삼는다** — 둘 다 같은
비중으로 쓰면 산만해진다. teal은 "검증/신뢰" 톤, amber는 "발견/온기" 톤에
가깝다.

## 타이포그래피

- **UI/본문**: `IBM Plex Sans KR` (Google Fonts) — 깔끔하고 절제된 산세리프
- **데이터/코드/라벨/메타정보**: `IBM Plex Mono` (Google Fonts)
- **손그림 다이어그램 안 라벨(선택)**: `Nanum Pen Script` (Google Fonts, 한글
  손글씨체) — 오직 다이어그램 안의 짧은 라벨/화살표 주석에만 쓴다. 본문
  문단에는 절대 쓰지 않는다(가독성 붕괴).

## 다이어그램에 손맛 내기

매번 정교한 손그림 SVG를 새로 그리는 건 비용 대비 효율이 낮다. 대신
가볍게 흉내낸다:
- 도형에 `border-radius`를 좌우 비대칭으로(`border-radius: 255px 15px 225px 15px / 15px 225px 15px 255px` 식) 주고 `rotate(-1deg)`~`rotate(1.5deg)` 정도 살짝 기울인다.
- 테두리는 `--ink` 색의 2px 실선, 그림자 대신 살짝 어긋난 이중 테두리로 마커 느낌.
- 화살표/강조는 `--accent` 또는 `--warm` 한 가지만 칠한다(레퍼런스의 "흑백 선화 + 포인트 컬러 1개" 원칙).
- 라벨은 `Nanum Pen Script`, 본문/데이터는 절대 이 폰트를 쓰지 않는다.

## 인터랙션 무드

- 토글/스위치류 UI는 **알약(pill) 모양** + 고대비 + 스냅되는 슬라이드
  애니메이션(`transition: transform .18s cubic-bezier(.4,0,.2,1)` 정도).
- 버튼은 `border-radius: 999px`(pill) 또는 라운드, hover 시 톤을 살짝
  진하게/연하게만 바꾼다 — 그림자를 키우거나 확대하지 않는다(과한 모션은
  AI스러워 보이는 지름길).
- `prefers-reduced-motion`을 항상 존중한다.

## 아기자기한 디테일 — 절제해서

persona-studio류의 마스코트/가이드 캐릭터, 말풍선 안내, 진행도·배지 칩,
은은한 반짝임(파티클) 같은 디테일은 **페이지에 정말 필요할 때(온보딩,
멀티스텝 흐름, "지금 뭘 보고 있는지" 안내가 필요할 때) 한 곳에만** 쓴다.
비교/리포트처럼 정보 밀도가 중요한 페이지에서는 이런 디테일보다 스캔
용이성이 우선이다 — 억지로 캐릭터나 파티클을 끼워넣지 않는다.

## 절제 기준

기본 배경/여백/그리드/타입 스케일은 항상 미니멀하게 유지한다(카드 그리드,
넉넉한 여백, 일관된 폰트 크기 단계). 위의 손그림·인터랙션·아기자기한
디테일은 전부 **이 미니멀한 바탕 위에 포인트로만** 얹는 것이지, 페이지
전체를 게임처럼 만드는 게 아니다. 대담함은 한 곳에만 쓰고 나머지는 조용하게
유지한다.

## 각 테마(라이트/다크) 처리

`artifact-design` 스킬의 3-상태 테마 규칙(explicit light/dark stamp +
system 기본값)을 그대로 따른다 — 위 팔레트를 `:root`(라이트 기본)와
`@media (prefers-color-scheme: dark): :root:not([data-theme="light"])`,
`:root[data-theme="dark"]` 세 군데에 일관되게 반영한다.
