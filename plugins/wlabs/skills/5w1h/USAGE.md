# 5w1h 사용법

이미 있는 프로젝트/기능을 놓고 "추가 개발", "유지보수", "여러 접근방법 중
선택", "고려해야 할 사항 검토"를 5W1H(육하원칙) 관점으로 정리해주는
스킬입니다. `project-struct`가 만든 프로젝트 전체 분석 결과를 배경지식으로
활용합니다(없으면 이 스킬이 먼저 실행해줍니다). 별도 API 키나 외부 서비스
설정이 필요 없습니다.

> 신규 요구사항을 처음부터 정의하고 싶으면 이 스킬 대신
> `/wlabs:spec-writer`를 씁니다. 이미 있는 것을 놓고 "다음에 뭘 어떻게
> 할지" 생각을 정리할 때가 이 스킬(`5w1h`)의 역할입니다.

## 1. 호출 방법

자동으로는 실행되지 않습니다 (`disable-model-invocation: true`). 항상
명시적으로 불러야 합니다:

```
/wlabs:5w1h
```

## 2. 사용 흐름

1. **배경지식 확보**: 분석 대상 프로젝트에 `docs/STRUCTURE.md`가 있는지
   확인합니다. 있으면 그 문서(+ 관련 있으면 `docs/API.md`·
   `docs/EXTERNAL-SYSTEMS.md`)를 읽어 배경지식으로 삼습니다. 없으면
   먼저 `/wlabs:project-struct`를 실행해 산출물을 만든 뒤 이어서
   진행합니다.
2. 무엇을 분석할지(요구사항/작업 내용)를 대화로 파악합니다. 애매하면
   되묻습니다.
3. 관점을 고릅니다: 추가 개발 / 유지보수 / 접근방법 결정 / 고려사항 검토 /
   기타.
4. project-struct 산출물을 1차 소스로 삼아, 이번 주제와 관련된 부분만
   추가로 코드 조사(Grep/Glob/Read, 필요하면 git log/blame)합니다.
5. Who/What/When/Where/Why/How + 고려사항(Considerations)을 채운
   문서를 만듭니다. 필요하면 Mermaid 다이어그램도 포함합니다.
6. `docs/5w1h/{YYYY-MM-DD}_{제목}.md`로 저장합니다.

## 3. 결과에서 주의할 점

- H1 제목에는 주제에 맞는 이모지를, 각 `##` 섹션 제목에는 고정된 이모지를
  붙입니다(`references/5w1h-template.md`에 정해진 값). 문서마다 섹션
  이모지가 바뀌지 않으니, 여러 문서를 훑어볼 때 일관되게 보입니다.
- 마크다운 문서라 실제 폰트 크기는 조절할 수 없어서, H1 > H2 > H3
  헤딩 레벨로 시각적 위계를 표현합니다.
- "고려사항" 섹션은 관점과 무관하게 항상 채워집니다 — 내용이 적으면
  "특별한 고려사항 없음"이라고 명시되고, 섹션 자체가 생략되지는
  않습니다.
- project-struct 산출물이 이미 있으면 그 내용을 재조사하지 않고 그대로
  활용합니다 — 매번 프로젝트 전체를 다시 훑지 않습니다.

## 4. 자주 겪는 문제

- **project-struct 실행이 먼저 끼어들어서 오래 걸림**: `docs/STRUCTURE.md`가
  아직 없는 프로젝트에서 처음 실행하면 project-struct 전체 분석이 먼저
  돌아갑니다 — 한 번만 겪는 비용이고, 이후 같은 프로젝트에서는
  `docs/STRUCTURE.md`를 재사용하므로 빨라집니다.
- **project-struct 산출물이 오래돼서 실제 코드와 다름**: 이 스킬은
  `docs/STRUCTURE.md` 존재 여부만 확인하고 최신인지는 검증하지 않습니다.
  코드가 많이 바뀐 뒤라면 `/wlabs:project-struct`를 먼저 다시 실행해
  갱신해달라고 요청하세요.
- **spec-writer와 뭐가 다른지 헷갈림**: spec-writer는 "새 요구사항을
  처음부터 정의"할 때, 이 스킬은 "이미 있는 것을 놓고 다음 방향을
  검토"할 때 씁니다. 저장 위치도 다릅니다(`docs/analysis/` vs
  `docs/5w1h/`).

## 5. 개선/확장 아이디어

- 아직 실전 사용 데이터가 없어서, 관점(추가 개발/유지보수/접근방법
  결정/고려사항 검토)별로 실제로 어떤 항목이 더/덜 필요한지는 여러 번
  써보면서 다듬어질 수 있습니다.
- project-struct 산출물이 오래됐는지 자동으로 감지(예: 마지막 수정일과
  최근 커밋 비교)하는 건 아직 없습니다 — 지금은 사용자가 직접 판단해서
  재실행을 요청해야 합니다.
