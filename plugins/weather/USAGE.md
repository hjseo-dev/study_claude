# weather 사용법

서울 금천구 독산1동 기준 오늘 날씨(현재 기온, 오늘 최고/최저기온, 하늘 상태,
강수형태·강수확률, 습도, 풍속)를 기상청 단기예보 API로 조회해주는 스킬입니다.

## 1. 사전 준비: KMA_API_KEY 발급

1. [data.go.kr](https://data.go.kr)(공공데이터포털)에서 "기상청_단기예보 조회서비스" 활용신청
2. 인증키(서비스키) 발급 (무료)
3. 환경변수로 등록 (PowerShell, 영구 설정 - 새 터미널부터 적용됨)

   ```powershell
   setx KMA_API_KEY "발급받은_인증키"
   ```

   방금 설정했다면 **새 터미널을 열어야** 반영됩니다. 기존 터미널에서 바로
   써야 한다면 그 세션에서만 `$env:KMA_API_KEY = "발급받은_인증키"`로 임시
   지정할 수 있습니다.

   umbrella 스킬을 이미 쓰고 있다면 같은 `KMA_API_KEY`를 그대로 공유해서
   씁니다 — 따로 또 발급받을 필요 없습니다.

## 2. 호출 방법

Claude Code에서 아래 슬래시 명령을 입력합니다.

```
/weather:weather
```

(플러그인 이름과 스킬 이름을 콜론으로 이은 형식입니다. `/weather`만 입력하면
동작하지 않습니다.)

이 스킬은 "오늘 날씨 어때?" 같은 말을 해도 자동으로는 실행되지 않습니다
(SKILL.md의 `disable-model-invocation: true` 설정). 위 슬래시 명령으로
명시적으로 불러야 합니다.

## 3. umbrella 스킬과의 차이

| | `umbrella` | `weather` |
| --- | --- | --- |
| 다루는 것 | 비/눈이 곧 올지, 우산 필요 여부만 | 기온·하늘상태·습도·풍속·오늘 최고/최저기온 |
| 쓰는 API | 초단기실황/예보 (`getUltraSrtNcst`/`getUltraSrtFcst`) | 단기예보 (`getVilageFcst`) |
| 커버 범위 | 지금부터 1~2시간 | 오늘 하루 전체 |

"우산 챙겨야 해?"는 umbrella, "오늘 날씨 어때?"는 weather로 갑니다.

## 4. 결과 예시

```
🌤 오늘 독산1동: 15시 기준 23°C, 맑음. 오늘 최저 18°C / 최고 26°C. 강수확률 10%, 습도 55%, 풍속 2.3m/s.
```

시간대에 따라 다르게 나올 수 있는 두 가지 특수 상황이 있습니다 (둘 다 정상 동작입니다):

- **이른 새벽**(약 02~05시 이전): 그날의 최저/최고기온이 아직 발표 전이라 "아직 발표 전"으로 나옵니다.
- **자정 임박**(23시 발표분에 오늘 남은 시간대가 없을 때): 현재 기온/하늘상태 대신 "오늘 예보 시간 종료"로 안내하고 최저/최고기온만 전달합니다.

## 5. 자주 겪는 문제

- **`KMA_API_KEY가 설정되어 있지 않습니다` 오류**: 위 1번 단계를 다시
  확인하세요. `setx`로 설정한 직후라면 새 터미널(새 Claude Code 세션)을
  열어야 반영됩니다.
- **`setx`로 분명히 설정했는데도 계속 안 잡힘**: Claude가 도구로 `setx`를
  대신 실행해준 경우, 그 실행 환경이 샌드박스라서 진짜 사용자 터미널의
  레지스트리에는 반영이 안 될 수 있습니다. 이럴 땐 본인이 직접 실제
  PowerShell 창에 `setx` 명령을 쳐야 확실합니다.
- **최저/최고기온이 "아직 발표 전"으로 계속 나옴**: 정상입니다 — 그날의
  TMN(최저)은 새벽 2시, TMX(최고)는 새벽 5시 발표분에만 포함됩니다. 그
  시각이 지나면 채워집니다.

## 6. 개선/확장 아이디어

- 지금은 독산1동으로 위치가 고정돼 있습니다. 다른 동네를 보고 싶다면
  `scripts/check_today_weather.js` 상단의 `NX`/`NY` 값을 바꾸거나, 인자로
  지역을 받도록 확장할 수 있습니다.
- umbrella와 인증키 인코딩·KST 시간 계산 로직이 거의 동일하게 중복
  구현돼 있습니다. 두 스킬이 공유하는 유틸로 뽑아내면 유지보수가 편해집니다.
- 테스트 시나리오 중 "비/눈 오는 날"과 "새벽 미발표(TMN/TMX null)"는 아직
  실제 조건에서 라이브로 검증하지 못했습니다 — 다음에 해당 조건일 때 한 번
  확인해두면 좋습니다.
- `umbrella`/`home-eta`/`fconline`에도 weather에서 발견했던 것과 같은
  `process.exit(1)` 크래시 위험(비동기 작업 이후 강제 종료)이 남아있습니다.
  weather만 고쳤고 나머지는 아직 손대지 않았습니다.
