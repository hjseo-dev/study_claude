# FC 온라인 팀 매니저

넥슨 오픈API의 매치 정보 조회 기능으로 사용자의 최근 경기 데이터를 가져와,
포메이션·전술 경향·플레이 스타일·강약점을 분석하고 감독처럼 다음 경기를
위한 포메이션/전술 조정과 선수 보강 방향을 추천한다.

> 게임 닉네임과 API 조회 결과는 이 리포지토리(GitHub에 공개됨) 안 어디에도
> 저장하지 않는다. 항상 사용자 홈 디렉터리(리포 밖)의 로컬 설정 파일에만
> 저장한다.

## 실행 방법

1. 환경변수 `FCONLINE_KEY`가 설정되어 있는지 확인한다. 없으면 아래 "인증키
   설정" 안내를 사용자에게 보여주고 중단한다.

   Windows에서는 `setx`로 설정한 시스템/사용자 환경변수가 이미 실행 중인
   셸 프로세스에는 바로 반영되지 않을 수 있다. 일반 조회(`$env:FCONLINE_KEY`
   등)로 값이 안 보이면, 포기하기 전에 PowerShell에서
   `[System.Environment]::GetEnvironmentVariable("FCONLINE_KEY", "Machine")`
   (또는 `"User"`)로 시스템에 실제로 등록되어 있는지 먼저 확인하고, 있다면
   그 값을 스크립트를 실행할 자식 프로세스의 환경변수로 넣어 실행한다.

2. 이 스킬 디렉터리의 `scripts/fetch_recent_matches.js`를 Node.js로 실행한다.
   (스킬 로드 시 표시되는 "Base directory for this skill" 경로를 기준으로
   삼는다.)

   ```
   node <스킬 디렉터리>/scripts/fetch_recent_matches.js [limit] [matchtype]
   ```

   인자를 생략하면 최근 10경기, matchtype 50(공식경기) 기준으로 조회한다.
   사용자가 "최근 20경기", "감독모드 기준으로" 등 다른 조건을 언급하면
   `limit`/`matchtype` 인자를 조정해서 실행한다.

3. 표준출력 JSON의 `needSetup`을 확인한다.
   - `needSetup: true`면 아직 닉네임이 저장되어 있지 않은 것이다. 사용자에게
     "FC 온라인 게임 닉네임"을 물어본다. 답변을 받으면 아래 명령으로 저장한
     뒤, 2번부터 다시 실행해 실제 결과를 얻는다.

     ```
     node <스킬 디렉터리>/scripts/set_profile.js "<닉네임>"
     ```

   - `needSetup: false`면 바로 4번으로 진행한다.

4. 이 스크립트는 데이터를 가공하지 않고, 각 경기의 원본 응답(`matches[].detail`)을
   그대로 반환한다. 넥슨 오픈API의 정확한 응답 필드명은 문서화가 불완전하므로,
   분석에 들어가기 전에 **먼저 `matches[0].detail`(그리고 그 안의 선수 배열)의
   실제 키 구조를 확인**한 뒤, 아래 항목을 뽑아 경기별/누적으로 정리한다.

   - 경기 결과(승/무/패), 득점/실점
   - 사용한 포메이션 (아래 "포메이션 판단 방법" 참고 — API가 "4-2-3-1" 같은
     이름을 직접 주지는 않는다)
   - 점유율, 패스 시도/성공(성공률), 슈팅/유효슈팅, 코너킥, 파울, 경고/퇴장 등 팀 스탯
   - 포지션별 선수 평점, 득점/도움, 주요 개인 스탯(드리블 성공, 태클/차단 등)
   - `spidMeta`가 채워져 있으면 spId를 선수 이름으로 매핑해서 사용하고,
     `null`이면 spId 숫자를 그대로 표기해도 된다 (억지로 이름을 지어내지 않는다).

   ### 포메이션 판단 방법

   `matches[].detail.matchInfo[].player[]`의 각 원소는 `spId`, `spPosition`
   (숫자 코드), `status`(개인 스탯)를 가진다. `spPosition`은 팀 내 포지션
   슬롯 코드이며, 응답에 "포메이션 이름" 필드는 따로 없다. 대신 스크립트가
   함께 내려주는 `sppositionMeta.data`(형태: `[{spposition, desc}]`, 예:
   `{spposition:25, desc:"ST"}`)로 각 선수의 `spPosition`을 GK/RB/RCB/CB/
   LCB/LB/RDM/CDM/LDM/RM/RCM/CM/LCM/LM/RAM/CAM/LAM/RF/CF/LF/RW/RS/ST/LS/LW/
   SUB 같은 표준 약어로 변환한다 (`sppositionMeta`가 null이면 숫자 코드
   그대로 사용). `SUB`(28)는 선발이 아닌 교체 대기 선수이므로 포메이션
   판단에서 제외한다. 나머지 10명(GK 제외) + GK를 라인별로 묶어
   (DF: *B/*CB 계열, MF: *DM/*M/*AM 계열, FW: *F/S/W 계열) 각 라인 인원수를
   세면 "4-2-3-1", "4-3-3" 같은 표준 포메이션 표기를 재구성할 수 있다.
   경기마다 다를 수 있으니 경기별로 계산하고, 가장 많이 쓰인 조합을
   "주 포메이션"으로 보고한다.

   일부 경기의 `matches[].error`가 있으면 해당 경기는 제외하고, 성공한
   경기 수 기준으로 분석한다.

5. 10경기 데이터를 종합해서 아래 관점으로 분석한다.

   - **최근 폼**: 승/무/패 기록, 최근 흐름(연승/연패 여부)
   - **주 포메이션과 성과**: 가장 많이 쓴 포메이션(들)과 그 포메이션에서의
     승률/평균 득실차
   - **전술 경향/플레이 스타일**: 평균 점유율, 패스 성공률, 슈팅 정확도 등을
     근거로 점유율 기반 빌드업형인지 역습 위주인지, 공격적/수비적 성향인지
     서술
   - **강점/약점 포지션**: 평점이 낮거나 실점 상황과 자주 엮이는 포지션,
     반대로 기여도가 높은 포지션
   - **추천**: 위 분석에 근거해 (a) 포메이션 유지 또는 변경안과 이유,
     (b) 전술 지시 조정 제안(빌드업 방식, 압박 강도 등 데이터로 뒷받침되는
     범위 내에서), (c) 보강이 필요한 포지션과 그 포지션에 필요한 능력치
     방향(스피드/피지컬/패스 등)을 제시한다. 시세 조회 API는 호출하지
     않으므로 특정 선수 카드나 가격을 단정적으로 추천하지 말고, "이런
     유형의 선수/카드를 찾아보라"는 방향성 위주로 조언한다.

     **급여(연봉)/샐러리캡 관련 요청이 있으면:** 넥슨 오픈API에는 선수
     연봉이나 감독모드 샐러리캡 관련 필드가 전혀 없다 (2026-08-29 확인 —
     `match-detail`의 `player[].status`에는 spId/spPosition/spGrade와
     경기 스탯만 있고 급여 관련 키는 없음). 급여를 고려한 영입 추천을
     원하면 API로 조회하려 하지 말고, 사용자에게 **현재 총급여와 샐러리캡
     한도(또는 여유 급여)를 직접 물어본 뒤**, 그 한도 안에서 앞서 뽑은
     보강 방향(포지션/능력치)에 맞는 선수를 찾아보라고 조언한다.

6. 답변은 감독의 전력 분석 브리핑처럼 정리한다. [[feedback-result-emoji]]
   규칙에 따라 각 결과 줄 앞에 어울리는 이모지를 붙인다 (예: ⚽ 최근 전적,
   📊 전술/스타일, 🧩 포메이션 제안, 🛒 보강 추천). 여러 선택지 중 가장
   우선순위 높은 한 가지를 강조할 때는 "⭐ "로 시작하는 줄을 사용한다.

   `error: true`이면 `message`를 그대로 전달하고, 원인(인증키 미설정/만료,
   닉네임 조회 실패, 네트워크/API 오류 등)에 맞는 다음 행동을 제안한다.

7. 닉네임을 바꾸고 싶다는 요청(예: "닉네임 다시 설정해줘", "다른 계정으로
   봐줘")을 받으면 바로 새 닉네임을 물어보고 `set_profile.js`를 다시 실행해
   덮어쓴다.

## 인증키 설정

[openapi.nexon.com](https://openapi.nexon.com)에서 넥슨 계정으로 로그인 후
애플리케이션을 등록하면 API 키가 발급된다. 무료로 발급 가능하다.

PowerShell (영구 설정, 새 터미널부터 적용):

```powershell
setx FCONLINE_KEY "발급받은_API_키"
```

## 닉네임/ouid 저장 위치

`set_profile.js`가 닉네임을 넥슨 오픈API로 ouid(계정 식별자)로 변환한 뒤,
사용자 홈 디렉터리의 다음 경로에 저장한다 (이 리포지토리 밖이므로 git으로
추적/커밋되지 않는다):

```
%USERPROFILE%\.claude\skill-data\fconline\profile.json
```

## 참고: matchtype

기본값은 `50`(공식경기)이다. 다른 매치 타입(감독모드, 볼타 등)을 분석하고
싶다면 `fetch_recent_matches.js`의 두 번째 인자로 다른 코드값을 넘긴다.
전체 코드 목록은 `https://open.api.nexon.com/static/fconline/meta/matchtype.json`
에서 확인 가능하다 (2026-08-29 curl로 검증):
`30`=리그 친선, `40`=클래식 1on1, `50`=공식경기, `52`=감독모드, `60`=공식
친선, `204`=볼타 친선, `214`=볼타 공식, `224`=볼타 AI대전, `234`=볼타 커스텀.
